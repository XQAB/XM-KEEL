# XM KEEL for bixi 1.0.0

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这是 XM KEEL 的第一版，也是它独立成项目的第一版。**功能上没有新东西**：这一版做的全是名字——仓库、品牌、内部 crate、机内路径——外加一件必须同时做到的事：已经在跑的机器升上来，密码还能解、数据还能开。

## 这一版改了什么

1. **独立成仓**：搬到 `XQAB/XM-KEEL`，不再是 `kirklin/skyward` 的 fork。上游同步工作流、指向上游的 remote 都去掉了；README 写明「最初源自 kirklin/skyward（GPL-3.0），现由 XM KEEL 独立维护」。LICENSE 与原作者署名保留。
2. **品牌**：界面、文档、发布标题、在线更新、About 页的版本串一律 XM KEEL，About 现在显示 `XM KEEL 1.0.0`。
3. **内部 crate**：`crates/skyward-*` 的 21 个目录改成 `keel-*`，crate 名与 `use` 引用同步改成 `keel_*`，二进制名 `keel`。
4. **机内路径与迁移**：`/metadata/skyward` → `/metadata/keel`，`/skyward/run`、`/skyward/persist`、`/skyward/park`、`/skyward/wlan`、`device.toml` 与字体默认值 → `/keel/...`；镜像内目录 `keel/`，MTP 的 init 规则改名 `keel-mtp.rc`。
   - 升级时开机先搬目录：`/metadata/skyward` 在、`/metadata/keel` 不在，就把整份（`credential`、`settings.json`、`systems.toml`、`wlan/`）搬过去，搬完才读设置与密码。**不用重新输密码，/data 照旧打开。**
   - 两边都在时以新的为准，只补新目录缺的条目；搬失败只记 kmsg，下次开机重试。
   - 旧镜像里的 `skyward/device.toml` 仍然认，装在 recovery 槽里的老镜像不会被当外来镜像覆盖。

## 升上来要注意

- **不会自动更新到 1.0.0**：新编号从 1.0.0 起，1.0.13 的更新器看到 1.0.0 会判成不比本机新。请手动刷一次（[docs/ota-survival.md](../../docs/ota-survival.md) 的做法），之后按 XM KEEL 的编号走。
- 发布资产名仍是 `skyward-1.0.0-bixi-OS4.0.0.11.XOHCNXM.img/.zip`，旧更新器认这个前缀；`zip` 与裸 `.img` 两份都发。
- `/data/skyward/systems`、第二系统 `init_boot` 里的 `skyward/system.toml`、`skyward/map` 没改名——改一半会让已装的第二系统起不来；`Skyward/{backups,partitions,logs}`、`Download/Skyward`、插件目录、`/data/misc/wifi/skyward` 是用户自己的文件，也不动。

## 验证状态

- 三个提交（品牌 → crate 改名 → 路径改名+迁移）在 CI 上各自 Build 与 Preview 双绿；迁移的三个单测在主机上跑过。
- 真机：升级前后密码能否一次解开、`/metadata/keel` 是否成形、两槽 recovery 与第二系统是否照常启动——待真机验收。
