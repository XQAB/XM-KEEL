# Skyward for bixi 1.0.10

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

1.0.9 上真机之后主人报回来的一批界面问题，这一版收了四条：摸不到的重启页、时不时没反应的点击、外屏上被截断的英文、说不清自己在干什么的插件页。另外两条（浏览器重做、锁屏）不在本版，见文末。

## 本次变更（1.0.9 → 1.0.10）

1. **外屏划不到底，重启点不到**（主人第 3 项，本轮最卡的流程之一）。重启页把内容画在一张「恰一屏高」的画布上，而一页的滚动余量正是「画布高 − 屏高」，于是恒为 0：这台机手机主屏够长、六项目标加槽位加「滑动以重启」一屏放得下，所以从来没暴露；外屏短，内容溢出之后**页面根本不能滚**，滑块永远在屏外。改成与首页、设置页同样的写法（`long_page` + 按最后一笔内容裁底），页面高度随内容长，滑块滚得到。同一毛病的四页一并改：屏幕常亮、语言、槽位、fastboot；槽位页的三条提前返回也按各自内容裁底，不再留下可滚的空白。
2. **点击随机没反应**（主人第 6 项，这一批里最影响使用的）。按下之后手指哪怕只抖过 8 dp，这一下就从「按」变成「拖」，抬起时既不回弹也不触发，点击被静默吃掉。现在：页面照旧在 8 dp 之后跟手，但只要抬起时离按下点不超过 16 dp，就仍按点击处理，页面先退回原位再触发。还有第二处是改这里时才发现的——「拖过页面末端要回弹」那条判断排在点击前面，首页这种一屏放得下、根本不能滚的页面，抖动会把位移全记成越界拉伸，抬起只回弹、照样不点击；点击这一支现在排在回弹之前，位移退回去时顺带把拉伸抹平。
3. **About 上的英文值被截断**（主人第 4 项）。卡片每行固定高度、值单行绘制，放不下就裁：`OS4.0.0.11.XOHCNXM · the same as the device` 在外屏上只剩前半截。改成先量宽度，放不下的行把值另起一行、左对齐画在标题下面（含换行的值按行拆开），卡片高度按实际行数累加——不再有任何一格靠裁字收场。
4. **插件页说不清自己是什么**（主人第 5 项）。原来只有一串模块名和一句「点上面切换、点下面删除」，没说什么叫模块、它们住在哪、为什么 recovery 要列出来、在这里能不能装。页面现在先讲这段（KernelSU 模块在 data 分区、开机时由内核加载、能把系统拖到起不来、这一页只切换与删除、装模块要回系统里用 KernelSU 管理器），再列模块，最后才是逐条的操作说明。

## 没做的两条

- **浏览器界面（第 7 项）**：要对照 `Jamvii/skyward-for-aurora` 与 `Rinrroy/skyward-for-haotian` 两份实现重做，不是修补能了的事，单独一批做。两份源码已取回工作副本，尚未动本仓的浏览器页。
- **锁屏（第 8 项）**：查过全仓的 `Screen` 枚举、页面与文档，Skyward 里**没有任何锁屏页**，`Decrypt` 是 data 解密、`locksettings` 是读锁屏密码库，都不是主人看到期待的那个「锁屏界面」。也就是说它不是没渲染出来，是从未实现。要什么形态（进入前的一道闸门／要求锁屏密码／仿系统的锁屏）需要主人拍一下，再照那个形态做。

## 验证状态

- CI：`b038ab0d`（三页 + 点击 + About 排版 + 插件页文案）、`f1c27d74`（点击排在回弹之前）：Lint and test（host clippy `-D warnings` + 全部单测）、手机端 clippy、bixi recovery 打包与 `tools/verify-release.py` 自检，全绿。
- 新增单测 `a_tap_that_shakes_a_little_still_presses_what_it_landed_on`：在首页按下、手指下移 12 dp 再抬起，断言落在的那一项被按下（首页因此切到设置页）。这条在旧的 8 dp 判据下必失败；把点击那一支排到回弹之后，它也会失败——正是这两处代码的回归。
- 真机验收等主人：本轮四条里，外屏滚动与点击、About 换行、插件页文案都能在没有第二系统的机器上直接看。
- 双系统那条链（装第二系统、模拟 OTA 写槽、刷 recovery 两槽、forgotten 回收）仍无真机验收：这台机 `/metadata/skyward/systems.toml` 不存在，一个第二系统都没装过。

## 已知限制（与 1.0.9 相同，未变化）

- `user 999` 打不开（recovery 里 gatekeeper 起不来），不影响 user 0。
- 两块面板不能同时驱动。
- `.7z` 容器不支持。
- 系统「在线更新」页没有加速源。
- 双击亮屏的代价是熄屏时整机不再休眠。
- 只有「一个槽被更新写掉、既没有重新装过也没有 remove」才会留下 forgotten 的 root。

## 校验方式

只认 sha256：对照 `SHA256SUMS`，或直接

```
sha256sum skyward-v1.0.10-bixi-OS4.0.0.11.XOHCNXM.img
```

## 资产

| 文件 | 说明 |
| --- | --- |
| `skyward-v1.0.10-bixi-OS4.0.0.11.XOHCNXM.img` | 裸镜像，104857600 字节，直写 recovery 分区（`dd` 或 fastboot） |
| `skyward-v1.0.10-bixi-OS4.0.0.11.XOHCNXM.zip` | 同一镜像的 zip，自更新可直接吃 |
| `SHA256SUMS` | 上面两个资产的 sha256 |
| `skyward-v1.0.10-bixi-OS4.0.0.11.XOHCNXM.verify.txt` | `verify-release.py` 对本版镜像的自检报告 |

资产名里的 `OS4.0.0.11.XOHCNXM` 是 `[stock].version`，即出包用的基线包版本。这个 fork 只维护 bixi，因此发行里只保留这台机器的资产。

## 刷入

```
fastboot flash recovery skyward-v1.0.10-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → Skyward 更新」里取同一份 `.img`。
