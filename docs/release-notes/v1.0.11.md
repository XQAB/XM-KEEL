# Skyward for bixi 1.0.11

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这一版是 1.0.10 之后的六条收尾，全部落在界面与回归测试，不碰系统分区。最要紧的一条是 **1.0.10 镜像里带着一处会让搜索页直接崩掉的断言**——这一版把它换掉了，所以该刷。

## 本次变更（1.0.10 → 1.0.11）

1. **搜索页结果一变高就崩溃**（这一版必须刷的原因）。`app.rs::render()` 在「只重画变了的那几行」的路径上有这么一句 `assert_eq!(canvas.h, fresh.canvas.h)`，前提是「同一页重画一次，高度不会变」。1.0.10 里搜索页还是「恰一屏高」，前提成立；把搜索结果改成可滚动的长页之后，结果一条条进来页面就长高，这句断言直接把进程打死。现在不再假定高度：重画前先比，一样就照旧把行贴回去，不一样就整页按新高度重画一遍再挂上。1.0.10 的 `app.rs`（char 197364）里这句原封不动，所以这版不是“优化”，是补一个会在真机上直接崩的洞。
2. **specs 页内容超出画布**（外屏尤其明显）。这一页有十来张卡，cover 的屏比手机短，第一遍画在外屏那三屏高的画布上时内容到了 3644（画布 3600），最后一张卡和底下的 License/Fonts 两行落在画布之外、滚也滚不到。改成「先画一遍量出 bottom，再按 `fitted(t,bottom)` 的高度画第二遍」，和图片页同一套写法。
3. **整页重画时行贴不进去**（改第 1 条时连着的第二处）。`Canvas::put_rows` 只接受「源画布确实持有」的行；第 1 条改成整页重画后，`draw_ahead` 再按行贴就会撞上 `the rows put are held` 这条断言。现在整页重画的画布按它自己的高度持有全部行，贴行不再越界。
4. **外屏滚不到重启滑块**（1.0.10 已修，本版补回归）。新增 `the_restart_page_scrolls_on_the_cover_to_the_swipe_that_restarts`：在 1000×1200 的 cover 上按下、分 40 步拖到 `max_scroll()`（断言真的到底），再断言「滑动以重启」的滑块矩形在 cover 的 1200 像素以内。同时新增 `no_control_is_drawn_past_the_bottom_of_the_page_it_scrolls`，遍历重启/改名/日志/语言/时区/fastboot/无法启动/未处理/槽位/系统/关于/规格/图片/文件 14 个页面，断言没有任何控件的底边越过它所在画布的底边——这一条就是第 2 条的守门人，specs 越界时它会指名报 `Specs draws Open(FontLicense) past the bottom of the page it scrolls`。
5. **浏览器页的控件改成工具条**（对照 aurora 的第一刀，第 7 项继续分批）。原来「后退/前进/重读/收藏」是四行列表，把正文往下推；现在是一排四个圆角键，图标（斜线箭头、回转箭头、书签）加 11 dp 的短词，收藏已存时用强调色，正文从工具条下面开始。同一批里 `search` 与 `files_find` 也改成可滚动长页，并把「键盘盖住的行不给点击区」的过滤器去掉——被盖住的行现在能滚上去点到。
6. **锁屏闸门与三个新测试**（第 8 项的缺口）。仓库里本来有锁屏三形态（图案/数字/字母键盘 + `Action::Skip`「暂不」），`locksettings` 也在读 `/data/system/locksettings.db`；缺的是「开机不拦」。现在 `ui.rs` 在「没有保留密码可试、且确实有用户自己的系统还锁着」时调用 `ask_for_the_screen_lock()`，把 `Decrypt` 盖在首页前弹出，`Skip` 退回首页。解锁成功后的行为按现状（留在页上显示已解密，靠返回键走），是否自动回首页等主人拍板。

## 验证状态

- CI：`2587abde` → `e99a3c6c` → `b198656e` → `fbd5d71b` → `1bc1894f` → `5ffa1415` → `2237cc8f`，逐次跑 Lint and test（host clippy `-D warnings` + 全部单测）、手机端 clippy、bixi recovery 打包、`tools/verify-release.py` 自检。`2237cc8f` 的 Build 全绿，`skyward-ui` 单测 359 通过（含上面三条新增）。
- 本版没有新增「解锁后自动回首页」「FBE 联动」「Skip 去留」任何行为：主人还没拍板，保持 1.0.10 的现状。
- 双系统那条链（装第二系统、模拟 OTA 写槽、刷 recovery 两槽、forgotten 回收）仍无真机验收：这台机 `/metadata/skyward/systems.toml` 不存在，一个第二系统都没装过。

## 已知限制（与 1.0.10 相同，未变化）

- `user 999` 打不开（recovery 里 gatekeeper 起不来），不影响 user 0。
- 两块面板不能同时驱动。
- `.7z` 容器不支持。
- 系统「在线更新」页没有加速源。
- 双击亮屏的代价是熄屏时整机不再休眠。
- 只有「一个槽被更新写掉、既没有重新装过也没有 remove」才会留下 forgotten 的 root。
- 浏览器只做了控件工具条这一刀；aurora 的地址药丸、首页快捷瓷贴、图标底栏、标签页/下载页/完整模式与本仓「从 Skyward 更新里选本地镜像」的对接仍在后续批次。

## 校验方式

只认 sha256：对照 `SHA256SUMS`，或直接

```
sha256sum skyward-v1.0.11-bixi-OS4.0.0.11.XOHCNXM.img
```

## 资产

| 文件 | 说明 |
| --- | --- |
| `skyward-v1.0.11-bixi-OS4.0.0.11.XOHCNXM.img` | 裸镜像，104857600 字节，直写 recovery 分区（`dd` 或 fastboot） |
| `skyward-v1.0.11-bixi-OS4.0.0.11.XOHCNXM.zip` | 同一镜像的 zip，自更新可直接吃 |
| `SHA256SUMS` | 上面两个资产的 sha256 |
| `skyward-v1.0.11-bixi-OS4.0.0.11.XOHCNXM.verify.txt` | `verify-release.py` 对本版镜像的自检报告 |

资产名里的 `OS4.0.0.11.XOHCNXM` 是 `[stock].version`，即出包用的基线包版本。这个 fork 只维护 bixi，因此发行里只保留这台机器的资产。

## 刷入

```
fastboot flash recovery skyward-v1.0.11-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → Skyward 更新」里取同一份 `.img`，或在「从内部存储安装」里选它。
