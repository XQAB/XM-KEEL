# Skyward for bixi 1.0.12

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这一版是 1.0.11 之后的一批：浏览器补齐到 aurora 那套的形态（地址药丸、首页瓷贴、图标 dock、书签、历史、菜单、标签页），锁屏闸门和解密合成一步，另加「翻转 180°」手动开关，以及一条会让「点亮后第一下点不动」的触摸修复。不碰系统分区。

## 本次变更（1.0.11 → 1.0.12）

1. **「点了没反应」：点亮后的第一指被吞（这一版值得刷的一条手感修复）**。`app.rs::touch()` 里原本有这么一句：面板点亮后 400 ms 内落下的 `Touch::Down` 直接 `return Vec::new()`，只让它保持常亮。设计本意是「安装收尾把页面顶到手上时，别让还在移动的手按到重启」，但按下去的实际体验是：拿起手机、按电源键点亮、点一下——没反应。现在守卫按「谁点亮的面板」区分：**主人自己弄亮的**（双击亮屏，或按电源键）不吃下一指；**别的东西弄亮的**（安装收尾、插线、备份/下载/擦除结束）照旧吃，那道防线还在，回归测试 `a_stray_touch_just_after_an_install_lights_the_panel_presses_nothing` 继续守着。三个来源各一条测试。
2. **设置页「屏幕」段多一行「翻转 180°」**（第 1 项的 A 方案）。合盖倒过来拿时整页连同触摸一起转半圈：绘制前 `Canvas::turn_half()` 把整幅画布按像素成对交换，触摸按 `(w-x, h-y)` 换算，内外屏共用同一个开关。选择写进 `/metadata/skyward/settings.json`（和语言、亮度同一份），重启进 recovery 还在；旧文件没有这一行，按 `#[serde(default)]` 落在关闭状态，不会把老用户的屏翻过去。每次改动往 kmsg 打一行 `the pages are turned half a turn: true|false`，真机上 `dmesg | grep turned` 就能看。
3. **重力翻转为什么没做**。这台机器的加速度计三条路都探过：`/sys/bus/iio/devices/` 只有 PMIC 和充电芯片（无 `in_accel_*`），input 的 8 个节点里没有传感器，SSC 上 ADSP 查不到 accel 的 UID。剩下的路要走 QSH/QESDK + vendor sensor HAL，而 recovery 里没有 binder manager 给它起 multihal。这条挂在 issue #8，不做投机接线；之前那版临时的 `UPSIDE_DOWN` 原子位和传感器线程里读方向的代码已一并撤掉。
4. **锁屏闸门与 FBE 解密合成一步**。冷启动那道闸验过密码后不只是放行：拿这串密码直接走 `decrypt::Job::Unlock { closed, user, credential }`，把该用户的文件真正解开，闸门通过就等于解开了。测试断言 `closed` 里对应用户消失（`still_closed` 之后只剩另一个用户），不是「只放行」。解锁成功停在原地显示已解密，不自动回首页；底部「暂不解密」保留，点了退出页面、`closed` 不变、回首页。
5. **浏览器补齐到 aurora 的形态**（对照 `crates/keel/src/browser.rs`、`keel-net/src/web.rs`、`keel-ui/src/browser.rs`、`keel-ui/src/app/browser.rs` 四件套，一次一块推、逐块跑 CI）：
   - 地址栏是一枚药丸，左边地球图标，右边才是去/停；
   - 首页是卡片 + 瓷贴，不再是工具条下面一段文字；
   - 控件收成一排图标 dock（八个键），带一个回首页的键；
   - 「收藏」单开一页（`BOOKMARKS_KEPT = 40`，点条目直达、可删）；
   - 「历史」单开一页，最近访问倒序（`HISTORY_KEPT = 40`），和书签分开；
   - 「更多」菜单一页五行，装 dock 放不下的次动作；
   - 「标签页」：最多 8 个（`TABS_KEPT`），各自独立地址、页面、前进后退；关掉当前后下一个顶上来，关到最后一个剩一个空标签，第 9 个被拒。
6. **完整浏览器插件页 + 锁屏显示**。插件（full browser）有了独立页面，不再挤在设置里；锁屏闸门在试保留密码期间正常显示，不再被插件页面盖住。

## 已知限制（与 1.0.11 大致相同）

- 180° 只能手动拨，不跟随重力：传感器链路在这台机器上读不到（见第 3 条，issue #8）。
- `user 999` 打不开（recovery 里 gatekeeper 起不来），不影响 user 0。
- 两块面板不能同时驱动。
- `.7z` 容器不支持。
- 系统「在线更新」页没有加速源。
- 双击亮屏的代价是熄屏时整机不再休眠。
- 只有「一个槽被更新写掉、既没有重新装过也没有 remove」才会留下 forgotten 的 root。
- 浏览器这三块（药丸/瓷贴/dock）与后面那几页（书签/历史/菜单/标签页）已在代码里齐了，真机观感与 dock 键距尚未逐项验收。

## 校验方式

只认 sha256：对照 `SHA256SUMS`，或直接

```
sha256sum skyward-v1.0.12-bixi-OS4.0.0.11.XOHCNXM.img
```

| --- | --- |
| `skyward-v1.0.12-bixi-OS4.0.0.11.XOHCNXM.img` | 裸镜像，104857600 字节，直写 recovery 分区（`dd` 或 fastboot） |

资产名里的 `OS4.0.0.11.XOHCNXM` 是 `[stock].version`，即出包用的基线包版本。这个 fork 只维护 bixi，因此发行里只保留这台机器的资产。

## 刷入

```
fastboot flash recovery skyward-v1.0.12-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → Skyward 更新」里取同一份 `.img`，或在「从内部存储安装」里选它。
