# Skyward for bixi 1.0.13

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这一版只有一条新东西，但它就是现场那个 bug：**合盖熄屏、再按电源键点亮之后，副屏完全点不动**。修法是让副屏永不被 blank。不碰系统分区。

自 1.0.11 起这一轮的五件事（触摸守卫按来源豁免、翻转 180° 手动开关、锁屏闸门与 FBE 合成一步、浏览器补齐、副屏不 blank）都在下面，最后一件是这一版新增的。

## 本次变更（1.0.12 → 1.0.13）

1. **副屏不再 blank：合盖熄屏后点亮，副屏触摸不再全死（issue #9，这一版值得刷的一条）**。真机取证把链条钉死了：`FB_BLANK LP` / `FB_BLANK POWER DOWN` 之后紧跟 `xiaomi_touch_suspend_work`（touch id 1 = 副屏 Goodix GT9916K），驱动走 `goodix_ic_suspend` → `gsx_gesture_before_suspend enter gesture mode, type[0x1000]` → `Canceled by module:Goodix_gsx_gesture` → `Suspend end`，控制器就留在手势模式，只报手势不报触点（`event8` 一秒零事件，节点全在）。
   - 能把控制器拉回来的只有 `FB_BLANK_UNBLANK`：Android 侧那条链是 `UNBLANK` → `xiaomi_touch_resume_work` → `goodix_ic_resume` → `goodix_ts_resume` → `esd on` → `Resume end`（同时 `mode 19 Touch_Power_Status` 的 `val` 从 0 回到 1）。
   - recovery 的熄屏路径把面板 blank 掉（`rest()` = LP、`turn_off()` = POWER DOWN），点亮却只是把背光打上去、重画一帧，**从来不发 UNBLANK**；blank 过一次就再也回不来，直到重启。这就是「画面亮、手指不来」的确切机制。
   - 改法：`App::may_rest_in_the_dark(on_cover)` 对副屏一律返回假，`ui.rs` 里 `rest()` 与 `turn_off()` 对副屏一次都不调；背光为 0 时只把帧填黑、`present`+`settle`，DRM 不收 blank 通知，`xiaomi_touch` 不挂起，控制器不入手势模式。内屏一字未动，仍是熄屏休息（除非开着「双击亮屏」）。
   - **代价（必读）**：副屏零亮度亮着，`is_off()` 恒为假，`may_sleep` 随之恒为假——**合盖状态下 recovery 不再深睡，即使没接 USB**。熄屏放一会儿会比以前掉电快。recovery 是分钟级会话，这个代价是故意接受的（`app.rs` 的 rustdoc 里写着）。
   - 两条测试守着：副屏在「双击亮屏」开/关两种设置下都不休息；内屏照旧（开双击亮屏时不休息，关的时候休息）。

## 本轮其它（1.0.11 → 1.0.12 已发布，1.0.13 一并带着）

2. **「点了没反应」：点亮后的第一指被吞**。守卫原本不看来源，面板点亮后 400 ms 内的 `Touch::Down` 一律吃掉；现在按「谁点亮的面板」区分——主人自己弄亮的（双击亮屏，或按电源键 `key()` 里置 `owner_awake`）不吃下一指，别的东西弄亮的（安装收尾、插线、备份/下载/擦除结束）照旧吃。三个来源各一条测试，`a_stray_touch_just_after_an_install_lights_the_panel_presses_nothing` 继续守着。
3. **设置页「屏幕」段多一行「翻转 180°」**。合盖倒过来拿时整页连同触摸一起转半圈（绘制前 `Canvas::turn_half()`，触摸按 `(w-x, h-y)` 换算），内外屏共用。选择写进 `/metadata/skyward/settings.json`，重启进 recovery 还在；旧文件没有这一行，按 `#[serde(default)]` 落关闭，不翻老用户。改动往 kmsg 打 `the pages are turned half a turn: true|false`。重力翻转在这台机上读不到方向（IIO / input / SSC 三条都探过），挂 issue #8。
4. **锁屏闸门与 FBE 解密合成一步**。冷启动那道闸验过密码后不只是放行：拿这串密码走 `decrypt::Job::Unlock { closed, user, credential }` 把该用户的文件真正解开，闸门通过就等于解开了。测试断言 `closed` 里对应用户消失。解锁成功停在原地显示已解密，不自动回首页；底部「暂不解密」保留，点了退出页面、`closed` 不变、回首页。
5. **浏览器补齐到 aurora 的形态**（对照 `crates/skyward/src/browser.rs`、`skyward-net/src/web.rs`、`skyward-ui/src/browser.rs`、`skyward-ui/src/app/browser.rs` 四件套，一次一块推、逐块跑 CI）：地址药丸、首页瓷贴、图标 dock、书签单页（`BOOKMARKS_KEPT = 40`）、历史单页（`HISTORY_KEPT = 40`，倒序）、「更多」五项菜单、标签页最多 8 个（`TABS_KEPT`，各自独立地址与前进后退，关到最后一个剩一个空标签，第 9 个被拒）。

## 已知限制（与 1.0.12 大致相同）

- **合盖熄屏时整机不再深睡**（`may_sleep` 恒为假），熄屏掉电比以前快——这是副屏不 blank 的代价，故意的。
- **不要在 UI 跑着的时候用 `recovery capture`**：它会另起一个实例抢 `/dev/dri/card0` 的 master，与正在运行的 UI 相撞，**手机会直接重启**（重启后 USB 有时连枚举都不上来）。要抓屏走组合键：`event2`(KEY_POWER) + `event3`(KEY_VOLUMEDOWN) 150 ms 内按下，落 `/sdcard/DCIM/Screenshots`。这一条是 1.0.13 真机验证时踩出来的。
- 180° 只能手动拨，不跟随重力（issue #8）。
- 副屏只在合盖时接管；开机时清盖屏 logo 那次 `cycle()` 仍会 blank 副屏一次（`ui.rs` 里开机且手机开着那段），之后若「开盖开机 → 合盖 → 点亮」可能仍撞上旧问题，真机在验。
- `user 999` 打不开（recovery 里 gatekeeper 起不来），不影响 user 0。
- 两块面板不能同时驱动；`.7z` 容器不支持；系统「在线更新」页没有加速源。
- 只有「一个槽被更新写掉、既没有重新装过也没有 remove」才会留下 forgotten 的 root。
- 浏览器各页真机观感与 dock 键距尚未逐项验收。

## 校验方式

只认 sha256：对照 `SHA256SUMS`，或直接

```
sha256sum skyward-v1.0.13-bixi-OS4.0.0.11.XOHCNXM.img
```

| --- | --- |
| `skyward-v1.0.13-bixi-OS4.0.0.11.XOHCNXM.img` | 裸镜像，104857600 字节，直写 recovery 分区（`dd` 或 fastboot） |

资产名里的 `OS4.0.0.11.XOHCNXM` 是 `[stock].version`，即出包用的基线包版本。这个 fork 只维护 bixi，因此发行里只保留这台机器的资产。

## 刷入

```
fastboot flash recovery skyward-v1.0.13-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → Skyward 更新」里取同一份 `.img`，或在「从内部存储安装」里选它。
