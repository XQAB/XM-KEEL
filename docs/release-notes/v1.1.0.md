# Skyward for bixi 1.1.0

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这一版主要包含：sns 探针三处修复、/metadata 迁移顺序 bug 修复、截图名改 `_KEEL` 前缀、真机冷启动验收通过。

## 本次变更

1. **sns 探针三处真 bug 逐个抓出**（orientation.rs）：
   - 属性表回复消息号应为 `128`（`SENSOR_ATTRIBUTES`），而不是请求号 `1`；这会导致 `on_change` 恒为 false，程序又发 `513` 被拒，最终得到 `0 samples`。
   - `request_full` 的帧头 transaction 写成了 2 字节，而协议只用 1 字节；整条帧向后错开一个字节，服务端不识别。
   - 属性值的数字被包了两层（`field1 wire1` 即 `8` 字节 LE `u64`），`attribute_int` 只认 wire 0/5，漏了 wire 1。

2. **`/metadata` 迁移顺序 bug 修复**：
   - `crates/keel/src/migrate.rs` 的 `metadata()` 先 `if !old.exists() { return Ok(()) }` 再 `with_metadata(...)`；冷启动时 `/metadata` 未挂、`/metadata/skyward` 不存在 → 早退 Ok 不打日志 → `move_over`/`remove_dir` 全没执行。新写法把存在性检查挪进闭包，并在成功/失败各自打一行 kmsg，补测试。

3. **截图名改 `_KEEL` 前缀**：
   - `crates/keel-ui/src/fmt.rs:1504` 格式串从 `_Skyward.png` 改成 `_KEEL.png`；注释 1500 与断言 1637/1638 一起改；`crates/keel/src/full.rs` 的三处 `/sdcard/Skyward/plugins/chromium` **不动**（Chromium 插件按发行说明落点，改了已装插件消失）。

4. **真机冷启动验收通过**：
   - `eddf395` 把 `bring_up` 挪到线程后不再挡首帧，首页回到三秒级。
   - 六步自拉起：`15.745 the sensor service answers`、三个 daemon 全跑。
   - 折动 209 个样本 `0°→179°→0°`、`capfold_status` 确实随折动在 `0/1` 之间跳变。
   - `adsprpcd` 不是传感器链路必需件（`needed: false` 成立），dmesg 里无 `EBUSY`。

资产名里的 `OS4.0.0.11.XOHCNXM` 是 `[stock].version`，即出包用的基线包版本。该 fork 只维护 bixi，因此发行里只保留这台机器的资产。

## 刷入

```
fastboot flash recovery skyward-v1.1.0-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → Skyward 更新」里取同一份 `.img`，或在「从内部存储安装」里选它。
