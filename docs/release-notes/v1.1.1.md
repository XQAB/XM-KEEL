# XM KEEL for bixi 1.1.1

机型：小米 MIX Flip 2（`bixi`，SM8750，Android 17，A/B + 动态分区；出包基线 `OS4.0.0.11.XOHCNXM`）。

这一版改两件事：**给外屏加一个「翻转 180°」开关**（需要时开一次就记住，默认不动画面），外加**修好插件页把已装的插件显示成「未安装」**的老毛病。不碰系统分区，也不改传感器链路。

## 本次变更（1.1.0 → 1.1.1）

1. **外屏「翻转 180°」开关**。合盖后用外屏时，如果方向不对，可以在设置里点一下，整页连同触摸一起转半圈。
   - 新增配置项 `display.cover_turned`：**默认关**，`bixi` 上也是关（实测系统里外屏 `mDisplayRotation=ROTATION_0`，本来就不需要转）。
   - 设置页「屏幕」段新增一行「**外屏翻转 180°**」，就在原来的「翻转 180°」下面：**只影响合盖后的外屏，内屏不受影响**；点一下落进 `settings.json` 记住，之后按点的那一下来——不用改配置再刷机。
   - 设置页原来的「翻转 180°」开关**保留**，叠加在外屏这一级之上：内屏照旧受它控制，外屏那一级看上面那一行（没点过时就是 `display.cover_turned`），两级各管一级，互不顶掉。

2. **为什么不做「跟着重力转」**。recovery 里读不到重力方向：`accel`、`gravity`、`device_orient`、`screen_down` 都拿不到可用数据（六个候选逐个用 `514` 打，全是拒绝码或固定值；内核侧也没有 `i2c-dev.ko`／`spidev.ko` 这条路）。所以页面朝向只按开合判据——触摸驱动的 `capfold_status` 与 ADSP 上的 `hinge_angle`——决定，不做按重力的自动翻转。完整实测见 [`docs/sensors-in-recovery.md`](../sensors-in-recovery.md) §11。

3. **修好插件页的状态**：插件页原来只在「系统更新」那条路径上重新查一次，从设置「关于」点进去时不查；开机那次 `/data` 还没解开，于是装了插件也显示「未安装」。现在插件页每次打开都会问一次（`crates/keel-ui/src/app.rs` 的 `arrive_at` 给 `Screen::Plugin` 补了 `Effect::ReadPlugin`），并补了一条单测钉住这个返回。

## 验证状态

- 配置项本身、「内屏开关／外屏配置」两级叠加，以及新增的设置页「外屏翻转 180°」开关（`Option<bool>`：未点过 = 跟随配置默认，点过 = 用户选择优先）：代码侧，随本版 CI（Lint and test、手机端 clippy、bixi recovery 打包、`verify-release.py` 自检）一起走。
- 外屏默认朝向已按系统配置确认：Android 侧 `dumpsys window displays` 显示外屏 `mDisplayRotation=ROTATION_0`（与内屏相同），所以默认不转；「外屏翻转 180°」开关的渲染与点击行为随本版 CI（含 `keel-ui` 单测）一起走，真机上点一下即可确认。

## 已知限制（与 1.1.0 大致相同）

- recovery 内无重力数据源，页面不会跟着手机转动自动换向，只有合盖这一路。
- 「翻转 180°」是整页连同触摸一起转半圈的手动开关，语义没变；它管内屏，外屏那一级看「外屏翻转 180°」这一行，没点过时才看配置项。

## 校验方式

`sha256sum -c SHA256SUMS`，或对单个 `.img` 跑 `sha256sum`；再对照 release 里的 `.verify.txt`（本版镜像的自检报告）。

## 刷入

```
fastboot flash recovery skyward-v1.1.1-bixi-OS4.0.0.11.XOHCNXM.img
```

这台机器用 `fastboot flash recovery` 刷 100 MB 的镜像会在中途断链（`Write to device failed (no link)`），更可靠的是在本机 root shell 里 `dd if=…img of=/dev/block/by-name/recovery_a bs=1048576`；也可以直接在 recovery 的「设置 → XM KEEL 更新」里取同一份 `.img`，或在「从内部存储安装」里选它。
